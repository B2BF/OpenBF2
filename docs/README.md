## Data tables read by tools

These files are inputs or default outputs of committed tools and tests; edit them only through
those tools:

- `ai-reconstruct/ledger.csv` (read by `Code/Tests/test_ai_static_init.py` and the
  `tools/ai-reconstruct` and `tools/tracks/dbg` scripts), `ai-reconstruct/ledger-summary.md`,
  `ai-reconstruct/console-bindings.json` (`tools/ai-reconstruct/build_ledger.py`,
  `gen_console_bindings.py`).
- `tracks/rend/`: `ledger.csv`, `ledger-summary.md`, `rdebug-map.csv`, `attribution.csv`,
  `attribution.md` (`tools/tracks/rend_ledger.py`, `tools/tracks/attrib/`, `tools/tracks/pe_evidence.py`).
- `tracks/srv/ledger.csv`, `ledger-summary.md` (`tools/tracks/srv_ledger.py`);
  `tracks/dbg/aidll_r_functions.csv` (`tools/tracks/dbg/anchor_table.py`).
- `tracks/swf/`: `ledger.csv`, `ledger-summary.md`, `swiffplayer-gameswf-functions.csv`, the
  `s1-*.csv`/`s1-inputs.json`/`s2-scope.csv` tables and the `*-ledger-overrides.csv` files
  (`tools/tracks/swf_align.py`, `tools/tracks/swf_ledger.py`).

[AGENTS.md](../AGENTS.md) is the working policy. Third-party documentation stays with its
dependency under `Code/BF2/External/`. The validation commands are in the development guide,
with harnesses in `Code/Tests/` and `Code/Build/`. Compilation, a successful link and a
runtime milestone are different results; check the paths a test exercised before drawing
conclusions.

## Where to put new information

Keep slice notes out of the repository: slice and investigation reports, progress logs,
hand-off notes, agent task prompts, audit tables and run logs are working material, not
documentation. Fold anything a developer needs later into the guide it belongs to, or into the
source comment beside the code with its retail evidence; never cite a working note from code.

Keep stable explanations of how to build, navigate, and change the engine in these guides.
Keep function and class comments focused on ownership, ordering, ABI constraints, surprising
behavior, and unresolved work. Public documentation must state the contract or limitation
directly. Describe the implementation and test conditions required to remove a temporary
boundary beside its source marker. Keep guides focused on how the engine works and how to
change it safely.

## Method and confidence

1. Pin a private copy of the symbolized Mach-O x86_64 archive. Verify the original DLL is PE i386 at 0x10000000. Extract exact strings, import/API names, ordered direct calls, literal constants, indirect jumps, PE vtables and native pointer-table relocations in both `__text` and `__StaticInit`. Keep duplicate archive member names separate. Follow reachable instruction edges rather than using Ghidra's summed body size as an end address; a vtable leaf ends at its own return. Restart disassembly at entries where the linear listing lost synchronization. Unresolved indirect jumps retain the bounded listing, with the incomplete-CFG flag visible in CSV.
2. Associate native symbols with brace-parsed definitions and ConsoleClass<__LINE__> symbols whose TU, actual source macro and Clang closing-line expansion agree. Seed from existing cited definitions; reject extreme size contradictions and tiny import helpers misclaimed as large engine methods. New own-address comments in the current source are `cited`, since the input ledger predates them.
3. Pair unique shared literals and D3D/D3DX APIs, then propagate through explicit MSVC-order adapter tables (three agreeing paired slots and equal table length), bracketed callee gaps, unique ordered paired-callee lists and single unmatched callers with agreeing already-paired caller sets. The explicit adapter pass excludes Itanium vtables. A separate C++ table pass requires a paired owner's retail table reference and native relocation, three agreeing ordinary method identities, one measured slot delta and matching full lengths. Destructor positions never provide anchors. Conflicting candidate votes, disjoint shared literals, contradictory high `_r` own-file sites and stopping/partial source bodies block pair acceptance.
4. Read EH FuncInfo/TryBlockMap tables reached through actual `__CxxFrameHandler` thunks. Classify outlined catch functions and exact this-adjusting/deleting-destructor wrappers as compiler machinery. Read CRT `_initterm` range arguments and its actual initializer pointers. Classify only short global-object destruction thunks registered by those initializers. Plain calls to `std::string` do not establish an STL function: require container diagnostics plus a throw in a bounded kernel without business strings/virtual calls, a recognized STL symbol, or the full instruction shape of an inspected `_Tree` rotation.
Full reachable-instruction signatures additionally recognize subtree erase, iterator-range erase and vector insert-n kernels. Their sentinel/deallocation or diagnostic/capacity-growth anchors must agree; classification is never propagated to their arbitrary callees. Initializer-registered destruction wrappers are traced even when Ghidra omitted the initializer entry.
5. Generated console constructors require their unique command literal, an actual retail CRT initializer caller, the current source macro invocation and the corresponding native class vtable installation in `__StaticInit`. Their constructors are inlined in the native TU initializer. For each console class separately, derive the ordinary-slot mapping from at least four exact retail metadata getter bodies and the native getters' symbol names. Require every delta and full table length to agree; never assume a destructor shift. 340 console tables passed these checks. The deleting-destructor position is excluded from that ordinary-slot pass.
6. Other `inlined` helpers have a retail direct caller already paired with a complete native body, and the helper's unique literal/API relocation resides in that native caller. Editor scope requires a retained retail file site, a high `_r` own-file site, or a named TerrainEditable interface declaration; neighbour guesses alone never exclude game work.

Category precedence is compiler/CRT/STL, then a cited or matched complete definition, then inlining, then editor scope, then missing. Thus an implemented editor function stays cited/matched, and an outlined catch does not become a false method match merely by sharing its message.

`high` requires two independent agreeing anchors (for example two distinct unique literals, a table reference plus the matching compiler pattern, or an STL diagnostic plus its exception path). `medium` has one accepted identity/scope anchor; `low` is review only. File neighbours and caller-file votes are always marked `[INFERRED]`. Candidate conflicts remain visible in CSV evidence.

Pairings identify source definitions and compiler roles; they are not new prototype/layout recovery. A native signature, chosen helper name or inferred file is not proof of the original PE ABI. Check caller instructions, argument preparation and return use before any subsequent code recovery.

The committed CSV evidence keeps only anchors and probable_file. Full evidence is in `out/attrib/attribution-evidence.csv`, including all retained strings, direct callees, imports, indirect call operands, raw caller callsites, `_r` match/file evidence and probable-file basis. Calls from code Ghidra did not make into a function retain the callsite; a CRT/EH-table-derived caller is labeled as such. Virtual-call reachability and register-indirect targets are not fabricated.
